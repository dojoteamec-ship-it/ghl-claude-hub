# Decisiones

Registro de decisiones técnicas. Formato: fecha, decisión, razón. La más reciente va al final.

| Fecha      | Decisión                                                                                                                                                                          | Razón                                                                                                                                                                                                     |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-10-20 | TypeScript estricto sobre Node 20 o superior, monorepo con workspaces de pnpm.                                                                                                    | Es la recomendación del plan: el SDK oficial de GHL y el SDK de MCP son de TypeScript. pnpm maneja bien los workspaces y es rápido.                                                                       |
| 2026-10-20 | Identificadores de código en español (`ProveedorSubcuentas`, `buscarContactos`). Se mantienen en inglés solo los nombres impuestos por terceros (`locationId`, campos de la API). | Lo eligió Santi. Coincide con los nombres del plan.                                                                                                                                                       |
| 2026-10-20 | TypeScript fijado en `~6.0`, no en 7.                                                                                                                                             | `typescript-eslint` 8.72 solo admite TypeScript menor a 6.1. La versión 7 rompería el lint. Revisar cuando `typescript-eslint` admita la 7.                                                               |
| 2026-10-20 | Herramientas: ESLint 10 con `typescript-eslint` estricto, Prettier, Vitest y secretlint con `simple-git-hooks` y `lint-staged` en pre-commit.                                     | Son estándares, sin dependencias nativas y corren igual en la Mac, en CI y en Railway. secretlint corre con Node, así que no hace falta instalar gitleaks aparte.                                         |
| 2026-10-20 | secretlint usa el preset recomendado más reglas propias para el PIT de GHL (`pit-<uuid>`) y el token de bot de Telegram.                                                          | El preset no reconoce esos dos formatos, que son los secretos principales del proyecto.                                                                                                                   |
| 2026-10-20 | Validación de configuración con zod 4.                                                                                                                                            | El SDK de MCP usa zod para los esquemas de entrada. Así se usa una sola librería en el núcleo, el MCP y el bot.                                                                                           |
| 2026-10-20 | Las pruebas de integración contra GHL usan el sufijo `*.integracion.test.ts` y no corren con `pnpm test`.                                                                         | Así las pruebas corren en un clon limpio y en CI sin credenciales.                                                                                                                                        |
| 2026-10-20 | `GHL_API_VERSION=2021-07-28` como valor inicial en `.env.example`.                                                                                                                | Es el valor que usa el SDK oficial de PHP. Se verifica contra los endpoints reales en la Etapa 3 y se registra aquí.                                                                                      |
| 2026-10-22 | Camino A para el MCP oficial: una sola conexión `ghl-oficial` con OAuth, sin entradas por subcuenta ni `headersHelper`.                                                           | Con OAuth, `list_locations` devolvió 2 subcuentas (Ronin de Prueba y Tomás Figueroa RoninX) y se leyeron contactos de ambas pasando `locationId` en `execute_operation`. Con PIT, `list_locations` falla. |
| 2026-10-22 | Los argumentos del MCP oficial van en camelCase: `operationId`, `params`, `locationId`, `dryRun`.                                                                                 | Es el esquema que publica `tools/list` de `anthropic/v2`.                                                                                                                                                 |
| 2026-10-22 | `ghl-core` y el bot deben redactar los datos de seguimiento de los contactos (IP, navegador, UTM) antes de mostrarlos o guardarlos en logs.                                       | El contacto leído en la prueba trae esos campos completos.                                                                                                                                                |
